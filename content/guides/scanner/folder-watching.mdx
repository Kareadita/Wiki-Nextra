# Folder Watching

Folder Watching lets Kavita pick up added, changed and removed files without a manual scan or waiting for the scheduled one. It is on by default. You can turn it off for the whole server in [Server Settings](/guides/admin-settings/general#folder-watching), and each library picks its own mode on its [Folder tab](/guides/admin-settings/libraries#folder-watching).

## Modes <TagBadge major={0} minor={9} patch={2} /> [#modes]

| Mode | What it does |
|---|---|
| **Automatic** (Recommended) | Kavita picks the best way to detect changes for each folder |
| **File Watcher** | Uses the operating system's change events. Docker on a network share, Docker Desktop host folders and FUSE pools do not support this |
| **Polling** | Checks the folders on a schedule. Slower than File Watcher, but works everywhere |
| **Off** | Changes are picked up by the scheduled scan or a manual scan |

## How long a change takes [#how-long-a-change-takes]

A folder is scanned 30 seconds after its last change. If changes keep coming, it is scanned at most 10 minutes after the first one. A file still being copied holds the scan back, up to the same 10 minutes.

## Automatic [#automatic]

Kavita looks at what kind of mount each folder is on:

- **Network mount:** the library uses Polling from the start. One folder on a network mount makes the whole library poll. Kavita treats these as network mounts: `cifs`, `smb3`, `smbfs`, `nfs`, `nfs4`, `9p`, `virtiofs`, `fakeowner`, `afpfs`, `webdav`, `macfuse`, `osxfuse` and anything starting with `fuse.`
- **Any other mount:** the library starts in **Testing**. Kavita uses the watcher and checks it against each scan. Once the watcher has seen the changes of 3 scans, and one full library scan found nothing it missed, the status becomes **Watching**.

### When the watcher fails [#when-the-watcher-fails]

A library moves to Polling when either of these happens, and you get a `Library is now using Polling` message in the event widget:

- A scan finds a change that the watcher never reported.
- A folder's watcher has 3 errors within 10 minutes. Errors within the same minute count as one.

It stays on Polling until you press **Retry** on the library's Folder tab. A library set to **File Watcher** instead of Automatic keeps watching after a missed change, and the Status line shows what was missed.

## Polling [#polling]

Each pass reads the time of every known folder, then hands the changed ones to a scan. The wait between passes is at least 60 seconds, and at least 10 times as long as the last pass, so a 9 second pass waits 90 seconds and a 5 minute pass waits 50 minutes.

<Callout type="warning">
  A file replaced in place may not change its folder's time, so a pass won't see it. It shows up at the next scheduled scan.
</Callout>

A folder that belongs to two libraries is polled if either library polls.

## Status [#status]

The library's Folder tab shows what Folder Watching is doing right now:

| Status | Meaning |
|---|---|
| **Off** | Folder Watching is off for the server |
| **Not watched** | The library's mode is Off |
| **Testing** | Watching, and checking the watcher against each scan |
| **Watching** | The watcher passed its checks |
| **Polling** | Kavita checks the folders on a schedule |

## Folders that are skipped [#folders-that-are-skipped]

Some folders are always ignored, such as `#recycle` and `@eaDir`. See the [full list](/guides/scanner#folders-kavita-always-skips).
