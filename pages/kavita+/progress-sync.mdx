# Progress Sync (Scrobbling)
Scrobbling is the act of synchronizing certain activities done on a Server, like Kavita, to an upstream provider, like AniList. 

Kavita supports:
- AniList
- MAL
- Mangabaka
- Hardcover[*](/kavita+/hardcover-scrobble-condition)

Each provider in Kavita (`Connections` setting page) can be configured for which functionalities you want processed.

![connections](/kavita+/scrobbling/connections.png "connections")


## Connect a Provider

Kavita uses OAuth to manage authentication tokens. 

1. Click `Connect` on the provider
2. Click `Connect Account`. This will launch the OAuth flow and will redirect you back to Kavita.
3. In the case you are not redirected, you will find in the URL something like `?upstream=1&apiKey=dbbcf530-9p30-4f05-a0d7-04d4d9cb39f7`. You can copy the apiKey into Authentication token. 

![connect](/kavita+/scrobbling/connect.png "connect")

## Provider Settings

![settings](/kavita+/scrobbling/settings.png "settings")

Kavita provides the following settings:
- Sync Progress
- Sync Ratings: Kavita+ will map to your rating settings (ie 0-5, 10, etc on AniList)
- Sync Want to Read List
- Sync Reviews
- Review Target
  - Only You - Keep my reviews private. On AniList this will write to the Note field.
  - Friends - Let my friends see my review
  - Everyone - Make it public
- Library Restrictions
  - By default, allow all libraries to scrobble to this Provider. 
  - Optionally, supply a list of library and only these libraries will use this provider.
- Highest (inclusive) age rating that can be scrobbled
- Inactive/Dropped Series Rules
	- A set of flexible rules that marks a series as `Inactive` based on days since last read, and publication status

![drop-rule](/kavita+/scrobbling/drop-rule.png "drop-rule")


Currently, Kavita+ supports AniList for scrobbling and supports the following events:
- Reading Progress
- Want to Read -> Adds a series to Planning
- Rating a series -> Will map to your rating preferences

## Backfilling events

When you first setup a Provider, you are likely to want to ensure Kavita is in sync with your upstream provider. Use the `Backfill Events` button, per-provider to generate events based 
on your settings. This will generate a lot of scrobble work, so setup your settings first. This can be run at any time. **Scrobbling Providers take the highest of existing + Kavita.**

## Scrobble Holds

Sometimes you don't want a Series to ever reach a Scrobble Provider, this is where Holds come into play. You can toggle on/off the Scrobble hold system by clicking the button in the screenshot. 

You can view all scrobble holds on the `Scrobbling Holds` page.

![scrobble-hold](/kavita+/scrobbling/scrobble-hold.png "scrobble-hold")



## Restrictions
Kavita will not perform scrobbling under the following conditions:
- A previous scrobble attempt was made and the series was not found (Series is Blacklisted - Fix the match in [Matched Metadata](/kavita+/metadata#matched-metadata))
- The series has Don't Match set (Series -> Match -> Don't Match)
- The series has a Hold on it (user-specific scrobble hold)
- The library of that series has Scrobbling off (for all users)
- There is no external id set on the series (Similar to Series being Blacklisted, Match to correct)

Scrobbling will always ensure the highest between AniList and Kavita is taken. So if AniList has 10 volumes read and Kavita reports 5, nothing will change. This is to ensure users that use multiple syncing services or have an existing history will not have issues.

<Callout type="info">
	 Kavita will scrobble once every hour. This period is not adjustable. Kavita will always scrobble the highest between existing read points and Kavita's record.
</Callout>

## User Tokens (pre-v0.9.1)
When users on the server use Progress Sync (Scrobbling), their tokens expire sometimes. As of v0.8.5, if SMTP is setup and the user has a valid email, 
Kavita will email them to refresh their tokens twice before the token expires. In the case that nothing is refreshed, scrobbling will stop working. 

Admins can use this screen to keep an eye on their users and help nag them when they will be impacted. 

![manage-user-tokens](/kavita+/scrobbling/manage-user-tokens.png "manage-user-tokens")
![manage-user-tokens-reminder](/kavita+/scrobbling/manage-user-tokens-reminder.png "manage-user-tokens-reminder")

## Hardcover Scrobble Condition

Hardcover has a condition that the target Book must have an edition with Pages > 0. See an example [here](https://hardcover.app/books/otherside-picnic-light-novel-vol-10/editions).

Most books will have at least one edition, if yours is missing one, you can create one yourself or reachout for support in Hardcover's discord server.
